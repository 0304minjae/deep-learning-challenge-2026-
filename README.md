## 3. 왜 파인튜닝을 채택하지 않았는가

### 진단: 문제를 두 종류로 분리

베이스 모델 기준 `pass@32 = 0.8633`, `maj@32 = 0.7400`.

```
정답을 찾을 줄 아는데 투표에서 지는 문제   12.3%p  → 선택 개선으로 회수 가능
정답을 아예 못 찾는 문제                  13.7%   → 새 지식이 필요
```

득표율 구간별 정확도를 보면 오답이 특정 구간에 몰려 있습니다.

| 득표율 | 문제 수 | 정확도 | 오답 수 |
|---|---|---|---|
| 0~30% | 51 | 0.157 | 43 |
| 30~50% | 27 | 0.370 | 17 |
| 50~70% | 34 | 0.706 | 10 |
| 70~90% | 28 | 0.893 | 3 |
| 90%+ | 160 | 0.975 | 4 |

**문제의 26%에 오답의 78%가 집중**되어 있고, 득표율은 신뢰도 지표로 잘 보정되어 있습니다.

### 시도 1 — RFT (Rejection sampling Fine-Tuning)

모델이 스스로 생성한 풀이 중 정답인 것만 골라 재학습. train 8,000문제 × 4회 생성 후 정답 풀이 7,695개 수집.

| | 베이스 | RFT |
|---|---|---|
| maj@32 | 0.7400 | 0.7333 |
| pass@32 | 0.8633 | 0.8600 |
| 평균 득표율 | 0.726 | **0.751** |
| 파싱 실패율 | 1.70% | **0.99%** |

**득표율과 형식 안정성은 개선됐으나 정확도는 개선되지 않았습니다.**
정답 풀이만 학습시키면 "확신을 갖고 말하는 법"을 배우는데, 그 확신이 정답과 오답 양쪽으로 동일하게 향했습니다.
→ 모델의 오답이 무작위가 아니라 **체계적**이라는 것을 시사합니다.

### 시도 2 — 프롬프트 다양화

접근법이 다른 4종 프롬프트(기존/검산 강조/계획 우선/중간값 명시)로 샘플을 분산.

| | maj@32 | pass@32 |
|---|---|---|
| 기준선(1종) | **0.7433** | **0.8633** |
| 4종 혼합 | 0.7367 | 0.8567 |

`pass@32`가 상승하지 않았습니다. **네 프롬프트가 같은 문제들을 동일하게 틀렸다**는 뜻이며,
실패 원인이 접근법이 아니라 지식의 부재임을 확인했습니다.

### 시도 3 — 공개 데이터 SFT

`AI-MO/NuminaMath-1.5`에서 필터링·추출한 20,000개 + RFT 5,465개로 QLoRA 학습(15,000개 사용, 1에폭).

eval loss는 0.4006 → 0.3833으로 지속 하락했으나 `maj@32`는 0.7333, `pass@32`는 0.8500으로 **모두 하락**했습니다.

> 손실 함수(다음 토큰 예측)와 실제 목표(정답 정수 맞히기)가 다르다는 사례입니다.

또한 최적 체크포인트가 906 step 중 **900번**이었습니다. 과적합이 아니라 **학습이 부족한 상태로 종료**된 것으로,
어중간한 학습이 잘 조율된 Instruct 모델의 균형을 흔들기만 한 것으로 판단했습니다.

### 시도 4 — train 매칭 데이터로 재학습 (v2)

대회 train 문제를 NuminaMath와 문장 대조하여 참조 풀이를 결합. 12,198개 확보(답 불일치 1.8%만 제외).
LoRA rank 32→64, 학습률 1e-4→2e-4로 상향.

| | 베이스 | v2 |
|---|---|---|
| **pass@32** | 0.8633 | **0.8733** |
| 평균 득표율 | **0.726** | 0.650 |
| maj@32 | **0.7400** | 0.7300 |

**5번의 학습 시도 중 처음으로 천장(`pass@32`)이 상승**했습니다. 새 지식이 실제로 유입된 것입니다.
그러나 평균 득표율이 7.6%p 하락하여 다수결이 약해졌고, 순효과는 마이너스였습니다.

모델이 나빠진 것이 아니라 **출력 분포가 평평해진 것**입니다.
temperature를 0.8 → 0.7로 낮춰봤으나 득표율이 1.6%p만 상승했고 `maj`·`pass`는 완전히 동일했습니다.
학습으로 형성된 분포는 샘플링 파라미터로 교정되지 않았습니다.

### 시도 5 — 베이스 + v2 어댑터 앙상블

베이스의 집중력(득표율 0.726)과 v2의 커버리지(pass 0.8733)를 결합.
문제당 베이스 32표 + v2 32표 = 64표 다수결.

| | 로컬 maj@32 | 리더보드 |
|---|---|---|
| 베이스 단독 | 0.7400 | **0.78580** |
| 앙상블 | 0.7500 | **0.77737** |

로컬 300문제에서는 +1.00%p였으나 **McNemar z = 1.13으로 통계적 유의성이 없었고**(불일치 7개),
831문제 리더보드에서는 오히려 0.84%p 하락했습니다.

> 표본이 작은 로컬 실험의 개선은 신뢰할 수 없다는 것을 확인한 사례입니다.

### 결론

파인튜닝 시도는 모두 베이스라인 미만이었습니다. 가장 큰 제약은 **계산 자원**으로 판단합니다.
NuminaMath 265,882개 중 20,000개(7.5%)만을 T4 단일 GPU로 1에폭 학습했고,
두 차례 학습 모두 최적 체크포인트가 마지막 step 부근이었습니다(906 중 900, 1213 중 1200).
**한 번도 수렴에 도달하지 못한 상태**였습니다.

## 4. 답 추출기 설계

정답이 항상 정수인 대회 특성상, 후처리가 점수에 직접 영향을 미칩니다.

### 중괄호 짝 맞추기

```
\boxed{\frac{100}{4}}
```

정규식 `\\boxed\{([^}]*)\}`는 첫 `}`에서 끊겨 `\frac{100`만 추출합니다.
여는/닫는 괄호를 세는 방식으로 중첩을 처리합니다.

### `float()` 미사용

train 데이터의 최대 정답이 `3,431,577,212,128,939`(약 3.4×10^15)입니다.

```python
int(float("3431577212128939"))  # -> 3431577212128940  (1 차이)
```

float은 유효숫자 15~16자리까지만 정확하므로, 문자열 → `int()` 경로만 사용합니다.

### 정수가 아니면 기권

`\boxed{\frac{7}{2}}` 같이 정수가 아닌 답이 나오면 `None`을 반환하여 **해당 샘플을 투표에서 제외**합니다.
텍스트에서 임의의 숫자를 추출하면 정답 쪽 표를 깎는 노이즈가 되기 때문입니다.

### 처리하는 형태

| 입력 | 출력 |
|---|---|
| `\boxed{1,024}` | 1024 |
| `\boxed{3{,}431{,}577{,}212{,}128{,}939}` | 3431577212128939 |
| `\boxed{\dfrac{650}{5}}` | 130 |
| `\boxed{42 \text{ cm}}` | 42 |
| `\boxed{\left(\frac{100}{4}\right)}` | 25 |
| `\boxed{2\times10^{6}}` | 2000000 |
| `\boxed{\frac{7}{2}}` | None (기권) |

`notebooks/FINAL_submit_0831.ipynb`의 `[4]` 셀에 자체 검증이 포함되어 있으며, 실패 시 `assert`로 실행을 중단합니다.

### 필터링 절차

```

  → question_type == "math-word-problem"     631,522
  → problem/solution 유효성 Yes              584,752
  → 이미지 링크 없음                          569,438
  → 정수 답 (int64 범위)                     285,411
```

### 평가 문항 제거에 관하여

대회 데이터가 NuminaMath 계열에서 파생된 것으로 보입니다. 근거는 세 가지입니다.

1. train 127개 문항에 `cdn.mathpix.com` OCR 이미지 링크가 있으며 NuminaMath와 형식이 동일 (해당 127개는 주최 측 오류 목록에도 전부 포함)
2. `Problem N.` / `Task N.` / `A1`·`G1`·`NT1` 등 문제 번호 접두사가 일치
3. **로컬 검증 300문제 + 리더보드 831문제 중 973개(86%)가 NuminaMath에 존재**

따라서 학습 데이터에서 **해당 973개를 사전 제거**했습니다.
규칙 5.2a는 공개 데이터셋 사용을 허용하지만, 평가 문항이 학습에 포함되면
리더보드 점수가 부풀려져 실제 test 성능을 잘못 예측하게 되므로 보수적으로 처리했습니다.

문항 선별 없이 **무작위 추출만** 사용했으며, 평가 문항을 검색하거나 답을 조회한 사실은 없습니다.

### T4 관련 제약

- **bf16 미지원** (Turing, compute capability 7.5) → fp16 사용
- **FlashAttention-2 미지원** (Ampere 이상 필요) → vLLM이 대체 백엔드로 자동 전환
- LoRA rank 64에서 `paged_adamw_8bit`가 CUDA illegal memory access를 발생시켜 `adamw_8bit`로 변경
- 4bit 양자화 모델 + DataParallel 충돌 → `CUDA_VISIBLE_DEVICES=0`으로 단일 GPU 강제

### 커밋 모드 실행

Kaggle 대화형 세션은 유휴 시 커널이 재시작되므로 장시간 추론에 부적합합니다.
`Save & Run All`(커밋)로 실행하되, protobuf 버전 충돌을 아래 순서로 회피합니다.

```bash
pip install -U vllm
pip uninstall -y ray opentelemetry-exporter-otlp-proto-grpc opentelemetry-exporter-otlp
pip install --force-reinstall "protobuf==5.29.5"
```

커널이 부팅 시 protobuf 5.29.5를 이미 로드하므로, 디스크 버전을 메모리에 맞추는 방향이 유효했습니다.
